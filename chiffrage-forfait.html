Chiffrage forfait

Processus pour fixer le prix d’une mission au forfait. Le socle accélère la livraison ; le client paie le livrable, pas nos heures réelles.

Orienté Phase 0 : hypothèses à confronter aux missions réelles. Illustration : case study (Boomerang) · délai : delai-livraison · flow : flow-client.

En une phrase

Stratégie

On vend un résultat au forfait. Le prix s’ancre sur Asans (sans la brique métier, encore sur l’infra). A ne sert qu’à la digue économique × 2 — pas à fixer le devis. Pré-vente à × 1. Ligne transverse déploiement / validation : A + Asans (dans le delivery). On négocie sur le scope / Asans, pas en descendant vers la digue.
  • Pas de TJM public × jours réels.
  • Jamais afficher A, Asans, j·h, TJM — uniquement lots, critères, prix HT, jalons.
  • ~1 000 € / j·h = référence interne.
  • Pré-vente : × 1 sur Aprévente (hors delivery).
  • Déploiement / validation : ligne transverse delivery (A + Asans) — pas absorbée dans la conf d’un service.

Principe

Prix = Asans

Les lignes « quasi conf » (engine, subscriptions…) ont un A bas. Les chiffrer via A les écrase. On ancre le prix sur ce que le service aurait coûté sans la brique.

Pi = Asans,i × 1 000 €   (services et ligne déploiement / validation)
Pprévente = Aprévente × 1 × 1 000 €
Pdelivery = Σ Pi
Pbrut = Pprévente + Pdelivery

Inv / Exp = filtre de fit. Pour le prix : Asans,i ; pour la digue : Ai (y compris déploiement / validation).

Transverse

Déploiement / validation

Mise en place d’environnement, install runtime, smoke tests, recette technique — travail de delivery, pas de pré-vente. Souvent oublié ou fondu dans « conf engine » : à chiffrer en ligne dédiée.

Pré-venteDéploiement / validation
Nature Coût commercial Delivery (transverse)
A / Asans A seulement → ×1 A et Asans → P = Asans × 1k
Digue ×2 Hors Σ A delivery Dans Σ Ai
Asans — Même mise en place / validation sans playbooks, patterns d’env, harness smoke Forge

Déploiement initial du lot = dans le forfait. Run / exploitation courante = hors build (sauf lot ops borné à part).

Digue

Plancher économique (× 2)

Pdelivery ≥ 2 × Σ Ai × 1 000 €
Si Σ Asans,i < 2 × Σ Ai → remonter Pdelivery au plancher (ou no-go si C ne suit pas).

Le ×2 n’est ni un objectif de marge, ni une valorisation de la Forge. C’est une digue économique, introduite pour la Phase 0 afin de protéger le modèle. Il garantit que le prix du delivery reste au moins deux fois supérieur à la charge réelle estimée, afin de couvrir :

  • les aléas de réalisation ;
  • les périodes non facturables (prospection, administration, R&D, formation…) ;
  • l’investissement continu dans Kontiki Forge ;
  • une marge minimale viable en solo / binôme Phase 0.

Hypothèse de départ à confronter aux missions réelles et à ajuster si nécessaire. La digue n’est pas le plancher de négociation : on ne « descend » pas vers 2×A pour faire passer un deal — on réduit le scope (donc Asans) ou on refuse.

Cible / planchers

Trois niveaux

Pcible = Aprévente×1k + max(Σ Asans,i, 2 × Σ Ai) × 1k
Pplancher = Aprévente×1k + max(0,85 × Σ Asans,i, 2 × Σ Ai) × 1k
Pdigue = Aprévente×1k + 2 × Σ Ai × 1k
NiveauRôle
Pcible Proposition initiale (ancrage Asans).
Pplancher Plancher commercial de négociation (~15 % sous Σ Asans, sans descendre sous la digue). Au-delà : réduire le scope, pas le prix « au feeling ».
Pdigue No-go absolu. Pas une cible de discussion.

On propose Pcible. Négo entre Pcible et Pplancher (idéalement en réduisant le scope / Asans). Sous Pplancher → re-scope ou refuser. Sous Pdigue → no-go.

0,85 = hypothèse Phase 0 ; à recalibrer après missions.

Processus

Étapes (Phase 0)

  1. Filtrer — signaux + grille 02.
  2. Découper — services + ligne transverse déploiement / validation (capital réutilisé tel quel inclus).
  3. Par ligne delivery — Ai (digue) et Asans,i (prix). Pi = Asans,i × 1k.
  4. Pré-vente × 1 (hors delivery).
  5. Fixer Pcible, Pplancher, Pdigue.
  6. Client — lots, critères, prix HT, jalons.
  7. Signature — jalons (ex. 40 % / 60 %).
  8. Avenant — mêmes règles.

Apprentissage

Après mission

  • Par service — A réel vs estimé ; Asans ; Pi.
  • Lot — forfait ; marge = Pdelivery ÷ (ΣA × 1k) (doit rester ≥ 2).
  • Lecture — Asans trop bas sur conf → sous-vente ; compression sous Pplancher → revoir la discipline de négo ; dérive d’A → revoir la charge, pas brader Asans.

Budget client

Intégrer C

SituationAction
C ≥ Pcible Proposer Pcible.
Pplancher ≤ C < Pcible Réduire scope / Asans, ou compresser jusqu’au plancher commercial, ou refuser.
Pdigue ≤ C < Pplancher Pas une zone de « petit effort » : re-scope sérieux jusqu’à un nouveau Pcible′ ≤ C, ou no-go. Ne pas vendre le lot initial à prix digue.
C < Pdigue No-go (ou lot radicalement redécoupé).
C inconnu Proposer Pcible ; calibrer les Asans ensuite.

À éviter

Anti-patterns

  • Prix = f(A) (écrase le capital conf).
  • Traiter la digue ×2 comme plancher de négociation.
  • Omettre déploiement / validation (ou le fondre dans « conf engine »).
  • Traiter déploiement comme pré-vente (×1) — c’est du delivery.
  • Omettre engine / subscriptions « parce que c’est juste de la conf ».
  • Asans = « sans Kontiki ».
  • Asans tiré vers A pour « passer » le devis.
  • Afficher A / Asans / j·h au client.
  • Pré-vente en ×2 ou ×0.
  • Signer sous Pdigue.
