Délai de livraison

Fixer le calendrier client à partir de la charge réelle A. Le prix reste ancré sur Asans (chiffrage-forfait) — ne pas mélanger les deux.

Phase 0 · hypothèses à recalibrer. Illustration : case study.

En une phrase

Règle

Prix = Asans · Délai = A → calendrier. Le client voit des semaines (conditionnées aux inputs), jamais des j·h.

Formule

Phase 0

Délaisemaines = ceil( Σ Adelivery / C ) + Mclient
SymboleSensPhase 0
Σ Adelivery Charge réelle du lot (hors pré-vente) Somme des Ai du chiffrage
C Capacité nette / semaine sur ce lot Solo focus ≈ 3–4 j·h/sem · binôme ≈ 6–8
Mclient Attentes inputs, accès, recette, allers-retours Typiquement +1 à +2 semaines

C et Mclient = hypothèses de départ. Si le lot est le seul chantier et les inputs sont déjà là : C haut, Mclient bas.

Affichage

Côté client

On montreOn ne montre jamais
Délai en semaines (ou date cible) ; point de départ (kickoff / réception des inputs) ; hypothèses (accès, jeux d’essai, délai de recette client). A, j·h, C, Mclient, découpage interne.
Exemple : « Livraison du lot 1 sous 6 semaines à compter de la réception des accès API et du canal Teams de test. »

Garde-fous

À ne pas faire

  • Calculer le délai avec Asans (allonge artificiellement quand la Forge est efficace).
  • Promettre un délai sans conditionner aux inputs client.
  • Afficher une charge en j·h « pour justifier » le calendrier.
  • Oublier de recalculer le délai si avenant (ΔA).
  • Confondre délai de build et engagement de run / support.

Exemple

Lot type (13 j·h delivery)

HypothèseCalculDélai annoncé
Solo, C = 4, M = 2 ceil(13/4) + 2 = 4 + 2 6 semaines
Binôme focus, C = 7, M = 1 ceil(13/7) + 1 = 2 + 1 3 semaines
