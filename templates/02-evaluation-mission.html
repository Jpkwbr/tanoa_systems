Annexe

Signaux pour reconnaître un fit ?

Bille pour le commercial (découverte / premier contact). Ligne directrice : principes fondateurs. Ici : indices concrets pour qualifier vite — pas une checklist d’architecture.

Verts — approfondir

  • « Nos applications ne se parlent pas » / fichiers, FTP, copier-coller entre systèmes
  • Traitements longs, asynchrones, files d’attente, jobs qui plantent ou qu’on relance à la main
  • Besoin de bus / événements / découplage entre services
  • Alertes, monitoring, notifications quand un service ou un flux casse
  • Intégrer un outil métier (LIS, device, API tierce…) dans le SI existant
  • « On a déjà des services, on veut fiabiliser / industrialiser »
  • Décideur technique accessible + problème bornable en lots

Jaunes — cadrer fort avant devis

  • Gros SI + demande vague (« digitaliser », « moderniser la plateforme »)
  • Solution imposée (Kafka, microservices, outil X) sans besoin reformulé
  • Beaucoup de front / UX mélangé au besoin d’intégration
  • Pas d’interlocuteur tech — seulement achats ou direction générale

Rouges — écarter ou reformuler

  • Régie / renfort d’équipe sans livrable forfait
  • Refonte applicative générale hors intégrations / petite plateforme backend
  • Achat de licence ou support d’un produit (Kontiki vendu comme tel)
  • Mission one-shot sans levier : n’exploite ni n’enrichit le patrimoine
