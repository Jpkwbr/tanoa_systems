Case study — chiffrage

Exemple fictif Phase 0 appliquant les règles de chiffrage-forfait.html : filtre, A, coefficient Inv/Exp, budget C, affichage client.

Non référencé depuis la feuille de route. Société et chiffres inventés.

Contexte

Client : NutriLab (PME industrielle)

NutriLab a un ERP et un outil LIMS (labo). Aujourd’hui les résultats d’analyse partent en CSV par e-mail, puis quelqu’un les ressaisit dans l’ERP. Ça casse souvent ; personne n’est alerté tant qu’un commercial ne s’en plaint.

Contact entrant via le binôme commercial. Appel découverte 40 min. Décideur technique : le responsable SI (accessible).

02 · Cadrage

Lot 1 — périmètre

InOut
Flux LIMS → ERP pour 2 types de résultats ; reprises sur erreur ; journalisation ; alerte (mail) si échec répété ; doc d’exploitation ; critères d’acceptation. Refonte ERP / LIMS ; UI métier ; autres flux ; formation large ; run 24/7.

Inputs client reçus (specs API LIMS, accès bac à sable ERP) en 4 jours — cadrage 1,5 j·h. Total pré-vente : 2,75 j·h (≤ 3).

05 · Budget client C

Trois scénarios

En fin de cadrage, le responsable SI indique une enveloppe.

Gain net / personne = ordre de grandeur Phase 0 : forfait retenu × 50 % (partage binôme) × ~0,55 (reste après cotisations + IR, frais légers déjà nets) ≈ forfait × 0,275. Pas un conseil fiscal — dépend du véhicule (portage, SAS…).

C annoncé vs bande 39–52 k€ Décision Tanoa Gain net / pers. (estim.)
60 k€ C ≥ Pcible Proposer 52 k€. ~14 k€ (sur 52)
40 k€ Pmin ≤ C < Pcible Compresser au plancher 39 k€ (scope inchangé) ou réduire le lot (1 type de résultat) pour un P′ cible plus bas. ~11 k€ (sur 39)
30 k€ C < Pmin Réduire le scope jusqu’à Pmin′ ≤ 30 (ex. A′ ≈ 10 → Pmin′ = 30 k€) ou no-go — pas vendre à 30 k€ sur A = 13. ~8 k€ si P′ = 30 ; sinon 0

Suite du case study : scénario C = 60 k€ → proposition à 52 k€ (~14 k€ nets / pers.).
